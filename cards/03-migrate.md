# 任务卡 03：迁移一个批次

## 目标

把一个批次内的文档改成新体系：去重、归位、删过期内容、修入站链接。批次结束时验收成立，改动范围可核对、可回滚。

## 输入

- 本批次定义：一组文件，加一句验收。派发时没写清就停下来回报，不要自己扩大范围。
- `docs-plan/proposal.md` 的事实归属表，决定重复内容往哪归。
- `reference/layers.md` 的「一个事实一个家」「写作规则」「维护规则表」。
- `reference/checks.md` 里与本次改动相关的检查项，人工先过一遍。
- 新建决策记录时加 `reference/decisions.md`；启用双语时加 `reference/bilingual.md`。

处理顺序通常是：先确定归属页，把完整表述移过去，原位置改成一句链接；过期内容按内容级删除或转入决策记录；最后全仓搜索被引用路径，修复所有入站链接。归属页或决策记录不在本批文件里时，先回报需要跨批写入的路径，不要自行扩大范围。

## 产物

本批次文件内的文档改动，加上必要时的入站链接修复；`docs-plan/migrate/<批次>.md`，建议包含：

```markdown
# 批次报告：<批次>

## 1. 范围
| 文件 | 动作（保留 / 移动 / 合并 / 删除 / 重写） | 理由 |
## 2. 删除项与替代
| 删除内容 | 原位置 | 级别（文件 / 内容） | 替代位置或理由 |
## 3. 入站链接修复
| 源文件 | 原链接 | 新链接 |
## 4. 检查结果
| 检查 | 结果 | 失败项与处置 |
## 5. 回滚
写清要恢复哪些文件、删除哪些新建文件
```

## 完成标准

- 改动都落在本批文件、本批报告和报告里列出的入站链接源文件内，用 `git status --short` 核对过。
- 每个删除项都有替代位置或明确理由；文件级删除或移动事先问过用户。
- 死链和锚点按 `checks.md` 的思路人工核对通过，报告里能看出核对了什么。
