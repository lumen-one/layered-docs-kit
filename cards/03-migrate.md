# 任务卡 03：迁移一个批次

> 读取范围：本卡；分派 prompt 的「本批次」节（或 `docs-plan/batches.json` 当前项）；`docs-plan/proposal.md` 的事实归属表；`reference/layers.md` 的「一个事实一个家」「写作规则」「维护规则表」。
> 前置：层级与模板已建立。
> 产出：本批次 `files` 内的文档改动；`docs-plan/migrate/<batchId>.md`。
> 禁止：处理本批次之外的文件。

## 目标

把一个批次内的文档改成新体系：去重、归属、删除过期内容、修复入站链接。每批结束时检查通过，且改动范围可核对、可回滚。

## 步骤

1. 读批次定义，列出本批 `files` 与 `acceptance`。批次未提供时，读 `batches.json` 的当前项，不要自己扩大范围。
2. 按事实归属表处理每个文件：
   - 重复内容：确定归属页，把完整表述移到归属页，其他位置改为一句链接。
   - 过期内容：删除；本批 `deletion` 未标记用户确认时不得删除。有历史价值的内容按档位转入决策记录，`basic` 档转入提交历史或 CHANGELOG。
   - 无归属内容：放进它所属的层，或删除。
   - 缺失内容：只补本批次范围内的必需章节，不顺手扩写其他模块。
3. 全仓搜索本批文件的被引用路径，原子修复所有入站链接。移动文件时不要留重定向。
4. 运行死链、锚点、段落内硬换行与本批涉及的结构检查。
5. 写 `docs-plan/migrate/<batchId>.md`。

## 报告结构

````markdown
# 批次报告：<batchId>

## 1. 范围

| 文件 | 动作（保留 / 移动 / 合并 / 删除 / 重写） | 理由 |
|---|---|---|

## 2. 删除项与替代

| 删除内容 | 原位置 | 替代位置或「无，理由」 | 是否已获确认 |
|---|---|---|---|

## 3. 入站链接修复

| 源文件 | 原链接 | 新链接 |
|---|---|---|

## 4. 检查结果

| 检查 | 结果 | 失败项与处置 |
|---|---|---|

## 5. 范围核对

```sh
git status --short
git diff --name-only
git ls-files --others --exclude-standard
```

逐行确认都落在本批 `files` 内。`git diff` 只覆盖已跟踪文件，新建文件用 `git status` 与 `git ls-files --others` 核对。

## 6. 回滚

```sh
git restore -- <本批已跟踪文件>
# 本批新建的未跟踪文件逐个删除
```
````

## 验收

- `git status --short` 的每一行都在本批 `files` 内；`git diff --name-only` 与未跟踪文件均逐条核对过，报告第 5 节有记录。
- 每个删除项都有替代位置或明确的「无，理由」；删除类批次的用户确认已记录在 `state.md` 批次表备注。
- 死链、锚点检查通过；段落内无硬换行。
- 报告的六节齐全，回滚命令已替换成本批实际文件路径，可直接执行。
- 本批 `acceptance` 逐条满足。

## 禁止

- 顺手重写其他批次或无关模块。
- 删除有外部引用的文档而不确认。
- 为了让检查变绿而删除链接或段落。
- 把多个批次合并成一次提交。

## 回报

```text
产物：<改动文件清单>、docs-plan/migrate/<batchId>.md
范围核对：<n> 个文件，全部在批次内 / 越界 <文件>
检查：死链 <通过/失败>，锚点 <通过/失败>，段落内硬换行 <通过/失败>
未决问题：<无则写「无」>
```
