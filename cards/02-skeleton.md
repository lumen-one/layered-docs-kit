# 任务卡 02：建立层级与规则

> 读取范围：本卡；`docs-plan/proposal.md`；`docs-plan/batches.json`；`reference/layers.md` 的「作用域」「模块 README 契约」；`reference/decisions.md` 的「路径与状态」「文件结构」。
> 前置：提案已获用户确认。
> 产出：项目内的指令文件、层级目录、模板、决策记录目录；`docs-plan/skeleton-report.md`。
> 禁止：迁移存量文档内容。本阶段只建空结构与规则。

## 目标

让项目具备可导航的层级和可复制的模板，后续任何会话都能从根指令走到任一模块契约，不需要先理解整个方案。

## 步骤

1. 创建根级 `AGENTS.md`，只放每次会话都需要的 8–15 条规则，每条 1–3 行并链接归属页。不放教程、故事、长流程。已存在同名文件时按「合并、不删除既有规则」处理，并在报告中列出新增与保留项。
2. 为每个有独立规则的子树创建或合并 `AGENTS.md`，只放该子树规则；根文件不重复它们。
3. 创建 `docs/architecture.md` 与各层索引。索引只做导航，不复述内容。
4. 创建模板：模块 README（第 1–5 节必填，第 6–7 节可选）、决策记录（proposed / implemented / rejected 三种状态；archived 由归档流程产生，不单独建模板）、教程（前置条件、步骤、可验证结果、下一步）、参考页（用途、字段或 API、默认值、示例）。教程与参考页的最小章节以本句为准。
5. 创建决策记录目录，并从现有代码中已做出的关键决定提炼 1–3 条真实记录。只写已有的事实，不编造备选方案。`basic` 档位跳过本步，在报告中记「按档位不建 L5」。
6. 在现有 `package.json` / `Makefile` / CI 中加入脚本入口，不新建平行体系。
7. 写 `docs-plan/skeleton-report.md`。

## 报告结构

```markdown
# 层级建立报告

## 1. 创建清单

| 路径 | 类型 | 来源（提案章节） |
|---|---|---|

## 2. 导航验证

| 起点 | 路径 | 终点 | 结果 |
|---|---|---|---|

至少验证 3 条：根指令到架构页、架构页到核心模块、模块到参考页。

## 3. 模板验证

| 模板 | 复制到临时路径后章节检查 | 结果 |
|---|---|---|

## 4. 决策记录

| 路径 | 来源（代码事实） | 格式检查 |
|---|---|---|

## 5. 脚本入口

| 入口文件 | 新增命令 | 现有命令是否受影响 |
|---|---|---|

## 6. 未建项与理由

| 提案中的项 | 不建原因 | 何时补 |
|---|---|---|
```

## 验收

- 根指令每条规则都能点到归属页；没有一条是「以后再说」。
- 从根指令出发，经架构页能到达至少 3 个模块 README，链路中每个链接有效。
- 四个模板复制后都能通过对应检查：模块 README 用章节结构检查，决策记录用格式检查（启用 L5 时）；教程与参考页按第 4 步列出的最小章节逐项核对。都不需要手工补章节。
- 启用 L5 时，决策记录的 `Status` 与目录映射一致（`archived/` 对应 `Status: implemented` 加 `Archived:` 行），必备章节齐全。
- 脚本入口复用现有入口文件，`git status --short` 中没有新建的构建体系。
- 没有修改存量文档的正文。允许的例外：修复指向新层的链接。

## 禁止

- 一次把所有存量文档改成新模板。
- 创建空的 `docs/` 目录充数。
- 在模板里写项目特定内容。
