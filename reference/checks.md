# 参考：自动检查目录

> 被 `01-proposal`、`04-checks`、`05-audit` 引用。实现检查时按本文件的判定方式与失败信息要求执行。

## 默认组合

按 `profile` 选择，不要一次全上：

| 档位 | 检查项 |
|---|---|
| `basic` | 1 死链、2 锚点、3 模块 README 章节结构 |
| `medium` | 增加 4 决策记录格式、5 段落行宽、6 字数预算、7 引用 |
| `multilingual` | 增加 8 双语一致性、9 语言切换器 |
| 有生成物 | 增加 10 生成物新鲜度 |
| 可选 | 11 代码块类型检查、12 导出 JSDoc 检查 |

## 检查项

### 1 死链

- 判定：每个相对 Markdown 链接的目标文件存在。
- 失败样例：指向已删除文件的链接。
- 失败信息：来源文件、行号、链接文本、目标路径、修复动作（更新或删除链接）。

### 2 锚点

- 判定：跨页 `#fragment` 能在目标文件的标题中找到对应 slug。
- 失败样例：目标文件存在但标题已改名。
- 失败信息：来源文件、行号、目标文件、缺失 slug、最接近的候选 slug。

### 3 模块 README 章节结构

- 判定：前五节存在且顺序正确；可选章节不打乱前五节顺序。
- 失败样例：缺少 `Known Limitations`，或 `开发者视角` 插在 `快速开始` 之前。
- 失败信息：文件、缺失或错序的章节、期望顺序。

### 4 决策记录格式

- 判定：见 `decisions.md` 的「检查要点」。
- 失败样例：`implemented` 记录里出现 `## Proposal`；状态与目录不一致。
- 失败信息：文件、违反项、期望值、修复动作。

### 5 段落行宽

- 判定：段落内不出现硬换行；代码块、表格、列表保持原格式。
- 失败样例：一个段落在中间被回车断开。
- 失败信息：文件、行号、所在段落首行、修复动作（合并为一行）。

### 6 字数预算

- 判定：入口页字数不超过清单上限；未超限时保留至少 5% 余量；上限只能上调且需说明理由，下调需文档确实还有余量。
- 失败样例：根指令文件超过上限。
- 失败信息：文件、当前字数、上限、超出量、三个可选动作（迁移、压缩、上调并说明）。

### 7 引用

- 判定：正文不出现完整 commit 哈希；历史引用使用 tag 或 PR 编号；组织外链接已登记。
- 失败样例：正文写着 `commit 3f2a9c1`。
- 失败信息：文件、行号、违规片段、替换建议。

### 8 双语一致性

- 判定：见 `bilingual.md` 的「检查要点」。
- 失败样例：修改中文侧后未重录一致性记录；两侧表格列数不同。
- 失败信息：配对文件、不一致的章节或结构项、重新记录命令。

### 9 语言切换器

- 判定：中文侧 H1 之后有回链英文；英文侧有回链中文；生成式英文源豁免。
- 失败样例：`foo.zh.md` 缺少 `[English](foo.md) | 中文`。
- 失败信息：文件、缺失行、期望文本。

### 10 生成物新鲜度

- 判定：重新生成后与仓库内容逐字节一致；生成区标记完整、互不重叠。
- 失败样例：手工改了生成区里的一个表格单元格。
- 失败信息：文件、生成区起止行、重新生成命令。

### 11 代码块类型检查

- 判定：文档中标记为代码的示例纳入编译或类型检查。
- 失败样例：示例调用了已删除的函数。
- 失败信息：文件、代码块起始行、编译器错误摘要。

### 12 导出 JSDoc 检查

- 判定：每个导出有契约说明，函数含参数与非空返回值。
- 失败样例：新增导出没有注释。
- 失败信息：文件、导出名、缺失的注释项。

## 实现要求

- 每个检查必须有应当失败的样例，证明它真的会报错。样例放在测试夹具目录，不放进正式文档。
- 失败信息必须指出文件、位置、期望值与修复动作。
- 接入现有 `test` / `lint` / CI，不要求开发者记新命令。
- 不得为了变绿而删除有效规则；先判断是内容错还是上限错。
- 每个检查器独立成文件，便于并行实现。最后由一个串行会话统一接入入口脚本。
