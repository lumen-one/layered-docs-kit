# 参考：自动检查目录

> 被 `00-recon`、`01-proposal`、`04-checks`、`05-audit` 引用。实现检查时按本文件的判定方式与失败信息要求执行。

## 组合来源

档位对应的检查组合见 `reference/thresholds.md` 的「档位组合」。本文件只定义每个检查的判定方式与失败信息，不重复档位映射。

## 扫描范围与排除

文档类检查（1–9、13）默认扫描 git 跟踪与未忽略的 Markdown 文件；检查 10 扫描生成物本身，文件类型由生成器决定，不限 Markdown；检查 11 扫描 Markdown 中的代码块，检查 12 扫描代码文件。默认排除：

- `.git/`、`node_modules/`、`vendor/` 与构建产物目录（`dist/`、`build/`、`out/` 等）。
- 生成物目录，由提案第 5 节登记。
- 冻结归档区 `docs/decisions/archived/**`，只做检查 4 的哈希校验，不做其他检查。
- `docs-plan/`：计划与报告产物不是交付文档，不纳入死链、锚点、硬换行与字数检查。

单项检查可以在此基础上收窄，不得扩大。提案第 5 节必须写明超出默认范围的额外排除项。

## 检查项

### 1 死链

- 判定：每个相对 Markdown 链接的目标文件存在。
- 失败样例：指向已删除文件的链接。
- 失败信息：来源文件、行号、链接文本、目标路径、修复动作（更新或删除链接）。

### 2 锚点

- 判定：同页与跨页的 `#fragment` 都能在目标文件的标题中找到对应 slug。slug 按 GitHub 规则生成：转小写、去标点、空格转连字符、保留中文与字母数字。
- 失败样例：目标文件存在但标题已改名；同页链接指向已删除的小节。
- 失败信息：来源文件、行号、目标文件（同页写「本页」）、缺失 slug、最接近的候选 slug。

### 3 模块 README 章节结构

- 判定：前五节存在且顺序正确；可选章节不打乱前五节顺序。标题按语义匹配中英文别名，不要求逐字相同：`Summary`/`概述`、`目录`/`Table of Contents`、`快速开始`/`Quick Start`、`配置与使用`/`Configuration`、`Known Limitations`/`已知限制`。只按位置与语义判定，不按标题文本逐字比较。
- 失败样例：缺少 `Known Limitations`（`已知限制`），或 `开发者视角` 插在 `快速开始` 之前。
- 失败信息：文件、缺失或错序的章节、期望顺序、修复动作（补齐或调整顺序）。

### 4 决策记录格式

- 判定：见 `decisions.md` 的「检查要点」；存在归档区时，内容哈希与 `archived/.frozen.json` 一致。
- 失败样例：`implemented` 记录里出现 `## Proposal`；状态与目录不一致。
- 失败信息：文件、违反项、期望值、修复动作。

### 5 段落内不硬换行

- 判定：段落内不出现硬换行；代码块、表格、列表保持原格式。
- 失败样例：一个段落在中间被回车断开。
- 失败信息：文件、行号、所在段落首行、修复动作（合并为一行）。

### 6 字数预算

- 判定：入口页字数不超过提案第 5 节「字数上限清单」给的该页上限；字数指非空白字符数，中英文都按字符计。清单未覆盖的入口页跳过并提示补录。接近上限 95% 只提示，不作为失败。入口页指根 `AGENTS.md`、根 `README.md`、`docs/architecture.md`、`docs/README.md` 与提案字数清单登记的页面。模块 README 的 Summary 按 `reference/thresholds.md` 的「字数度量」计算，默认上限 100 词，提案可覆盖。
- 失败样例：根指令文件超过上限。
- 失败信息：文件、当前字数、上限、超出量、三个可选动作（迁移、压缩、上调并说明）。

### 7 引用

- 判定：正文不出现提交号（`commit` 后的 7–40 位十六进制，或裸 40 位十六进制）；历史引用使用 tag 或 PR 编号；组织外链接要么在 `docs/references-allowlist.yaml` 中登记，要么在当前运行模式可访问。运行模式取提案第 5 节登记值；未登记时按离线模式执行。离线模式只校验登记，不发起网络请求。外部链接的 fragment 不强制解析。
- 登记文件格式：每条包含 `url`、`owner`、`reason` 三个字段；文件不存在时所有组织外链接一律按失败处理。
- 失败样例：正文写着 `commit 3f2a9c1`；外部链接未登记。
- 失败信息：文件、行号、违规片段、替换建议或需补登的字段。

### 8 双语一致性

- 判定：见 `bilingual.md` 的「检查要点」。切换器只由检查 9 判定，本项不重复判定。
- 失败样例：修改中文侧后未重录一致性记录；两侧表格列数不同。
- 失败信息：配对文件、不一致的章节或结构项、提案第 5 节给出的重新记录命令。

### 9 语言切换器

- 判定：中文侧 H1 之后有回链英文；英文侧有回链中文；提案第 5 节登记的生成式英文源豁免。
- 失败样例：`foo.zh.md` 缺少 `[English](foo.md) | 中文`。
- 失败信息：文件、缺失行、期望文本。

### 10 生成物新鲜度

- 判定：按 L8 的两种形态分别判定。同页生成区：重新生成后与仓库内容逐字节一致，生成区标记完整、互不重叠；整页生成：重新生成整个文件后与仓库内容逐字节一致，文件头含生成器标识与重新生成命令。
- 失败样例：手工改了生成区里的一个表格单元格。
- 失败信息：文件、生成区起止行、重新生成命令。

### 11 代码块类型检查

- 判定：文档中标记为代码的示例纳入编译或类型检查。
- 失败样例：示例调用了已删除的函数。
- 失败信息：文件、代码块起始行、编译器错误摘要。

### 12 导出 JSDoc 检查

- 判定：每个导出有契约说明，函数含参数与非空返回值；只校验这些字段是否存在，不评价注释文风。
- 失败样例：新增导出没有注释。
- 失败信息：文件、导出名、缺失的注释项。

### 13 指令副本一致性

- 判定：每个 `AGENTS.md` 旁存在对应 `CLAUDE.md`；为软链接时指向同一文件，为同内容副本时与对应 `AGENTS.md` 逐字节一致。
- 失败样例：某个 `CLAUDE.md` 是副本，但内容与对应 `AGENTS.md` 不一致；或子树 `AGENTS.md` 缺少 `CLAUDE.md`。
- 失败信息：文件、不一致类型（缺失 / 链接目标 / 内容差异）、修复动作（创建链接或同步副本）。

## 实现要求

- 每个检查必须有应当失败的样例，证明它真的会报错。样例放在测试夹具目录，不放进正式文档。
- 失败信息必须指出文件、位置、期望值与修复动作。
- 接入现有 `test` / `lint` / CI，不要求开发者记新命令。
- 不得为了变绿而删除有效规则；先判断是内容错还是上限错。
- 每个检查器独立成文件，便于并行实现。最后由一个串行会话统一接入入口脚本。
