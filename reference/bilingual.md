# 参考：双语配对

> 被 `01-proposal`、`05-audit` 引用。仅在项目需要多语言时启用。

## 三件套

同一目录下三个同级文件：`foo.md`、`foo.zh.md`、一致性记录 `foo.i18n.yaml`。不用 `locale/` 目录，不混排双语。增加第三种语言时按同一模式扩展，例如 `foo.ja.md`。

## 权威对等

任一语言都可以先写、先评审，另一侧从它翻译。绑定两侧的不是「谁是源」，而是两侧必须说同一件事。

## 一致性记录

记录按标题章节组织。键是该节内容的英文标题 slug 路径；首个标题之前的内容用 `/`；同一 slug 重复出现时用 `~2`、`~3` 区分。值是英文块与中文块的哈希：

```yaml
/foo:
  en: 41d772192075e133
  zh: dda91c6c670cfd9d
/foo/usage:
  en: 86940bea4a3c7ed6
  zh: de78429597783c7f
```

哈希覆盖该节所有顶层块，排除围栏代码块与生成区；这两类内容必须在两侧逐字节一致，由结构检查单独约束。没有剩余块的章节不记条目。记录由命令生成，禁止手写；人工只负责确认「这两段确实对应」。重新记录，等于声明这一对当前一致。

```sh
# 示例命令形态，落地时换成项目内的脚本名
pnpm run docs:pair --write docs/architecture.md
pnpm run docs:pair docs/architecture.md   # 只校验
```

## 结构镜像

两侧的标题层级与顺序、列表类型与起始序号、列表项数、表格行列数、语义链接目标（含 query/fragment）、代码块（信息串与内容）逐项一一对应。相对文档链接在英文侧指向 `.md`，在中文侧指向 `.zh.md`。

## 配对范围

根级面向人的 md、每个非 vendor 的 README、`docs/**`、活跃决策记录目录。新增文档默认进入范围。

## 排除项

检查器发现这些文件旁出现 `.zh.md` 或 `.i18n.yaml` 应报错：

- 子树指令文件及其 `CLAUDE.md` 软链接：全仓用一种语言维护。
- 术语表、风格样例：本身按双语构造。
- 机器消费的提示词模板：配对会改变程序行为。
- 无中文对照的生成式英文源：是否产出对照由生成器决定。
- 冻结归档区：只读，不翻译。

## 能力边界

检查通过只说明「在这一份内容上确认过一致」，不说明翻译质量。质量由评审负责，检查替代不了评审。

## 检查要点

双语一致性检查必须覆盖：

- 范围内每个文档三件套齐全；排除项处不存在多余文件。
- 一致性记录可解析，条目与当前内容计算出的哈希一致。
- 结构签名逐项一致：标题层级与顺序、列表类型与起始序号、列表项数、表格行列数、代码块、语义链接目标。
- 中文侧有回链英文的切换器；英文侧有回链中文的切换器，生成式英文源豁免。
- 相对文档链接按所在语言指向对应后缀。
