# 参考：双语配对

项目需要多语言时再启用。核心是一句话：两种语言说的是同一件事。

## 三件套

同一目录下三个同级文件：`foo.md`、`foo.zh.md`、一致性记录 `foo.i18n.yaml`。不用 `locale/` 目录，不混排双语。加第三种语言时照同一模式扩展，例如 `foo.ja.md`。

## 权威对等

任一语言都可以先写、先评审，另一侧从它翻译。绑定两侧的不是「谁是源」，而是两侧说的是同一件事。所以不要设「英文永远权威」这类规则。

## 一致性记录

记录按标题章节组织。键是该节英文标题的 slug 路径；第一个标题之前的内容用 `/`；同一 slug 重复出现时用 `~2`、`~3` 区分。值是英文块与中文块的哈希：

```yaml
/foo:
  en: 41d772192075e133
  zh: dda91c6c670cfd9d
/foo/usage:
  en: 86940bea4a3c7ed6
  zh: de78429597783c7f
```

哈希覆盖该节所有顶层块，排除围栏代码块与生成区；这两类内容要求两侧逐字节一致，由结构检查单独约束。没有剩余块的章节不记条目。记录由工具生成，人工只负责确认「这两段确实对应」；重新记录等于声明这一对当前一致。

工具命令名与调用方式由提案按项目工具链确定，例如：

```sh
<docs:pair 写入命令> docs/architecture.md
<docs:pair 校验命令> docs/architecture.md
```

## 结构镜像

两侧的标题层级与顺序、列表类型与起始序号、列表项数、表格行列数、语义链接目标（含 query 和 fragment）、代码块的内容与信息串，逐项对应。相对文档链接在英文侧指向 `.md`，中文侧指向 `.zh.md`。

## 范围与排除

默认范围：根级面向人的 Markdown、每个非 vendor 的 README、`docs/**`、活跃决策记录目录。新增文档默认进入范围。

不配对：指令文件（每份 `AGENTS.md` 及其 `CLAUDE.md`，全仓用一种语言维护）、术语表与风格样例（本身按双语构造）、机器消费的提示词模板、由生成器决定的英文源、冻结归档区。

## 能力边界

检查通过只说明「在这一份内容上确认过一致」，不说明翻译质量。质量由评审负责，检查替代不了评审。
