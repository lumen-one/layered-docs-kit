# 参考：档位与阈值

> 被 `00-recon`、`01-proposal`、`04-checks` 引用。档位组合与数量阈值的唯一来源；其他文件只引用，不重复定义。未列入本表的数值不属于本体系约束。

## 档位组合

| 档位或条件 | 建议启用层级 | 检查组合 |
|---|---|---|
| `basic` | L0a + L1 + L2；不建 L5、L7 | 1 死链、2 锚点、3 模块 README 章节结构 |
| `medium` | 在 `basic` 上增加 L5、L7 | 增加 4 决策记录格式、5 段落内不硬换行、6 字数预算、7 引用 |
| `multilingual` | 在 `medium` 上增加双语三件套 | 增加 8 双语一致性、9 语言切换器 |
| 有生成物 | 不限档位，增加 L8 | 增加 10 生成物新鲜度 |
| 可选 | 不限档位 | 11 代码块类型检查、12 导出 JSDoc 检查、13 指令副本一致性 |

档位只影响建议层级与检查组合，不改变阶段顺序。项目确实不需要某档位默认项时，在提案第 2、5 节写明理由，可缩减；不得静默跳过。

## 数量阈值

| 参数 | 默认值 | 定义位置 | 调整方式 |
|---|---|---|---|
| 待迁移文档参考线 | 10 个 | 本文件 | 参考线；`README.md` 的选型按此值，项目可按会话容量调整 |
| 单批文件上限 | 8 个 | `01-proposal` 第 7 节 | 默认上限；确需放宽时在提案第 7 节写理由 |
| 提案待确认事项 | 3 条 | `01-proposal` 第 10 节 | 建议值；超过时合并同类项 |
| 根指令规则数 | 8–15 条，每条 1–3 行 | `02-skeleton`、`layers` | 建议值；规则少于 8 条时按实际，不凑数 |
| 决策记录提炼 | 1–3 条 | `02-skeleton` | 建议值；没有可提炼的决定时写理由 |
| 导航验证 | 3 条链路 | `02-skeleton` | 建议值；层级不足 3 条时按实际链路验证 |
| 漂移抽样模块 | 3–5 个 | `00-recon` | 建议值；模块不足 3 个时全覆盖 |
| 新成员测试页数 | 3–5 页 | `05-audit` | 建议值；一页能覆盖时只读一页 |
| 事实归属表条目 | 5–10 个 | `01-proposal` 第 4 节 | 建议值；事实少于 5 项时写明判断依据 |
| 启用/裁剪层级 | 逐项结论 | `00-recon` 第 4、5 节 | 每层写启用或裁剪的结论；无裁剪项写「无」并说明理由 |
| 同一任务重试上限 | 2 次 | `acceptance` | 固定流程上限，不随项目调整 |
| Summary 上限 | 100 词 | `layers`、`checks` 检查 6 | 默认值；提案第 5 节可覆盖 |
| 入口页字数提示线 | 上限的 95% | `checks` 检查 6 | 只提示，不作为失败 |
| 提交号识别长度 | 7–40 位十六进制 | `checks` 检查 7 | 硬约束，用于判定 |

## 字数度量

- **入口页**：按非空白字符数计算，中英文都按字符计；上限由提案第 5 节的「字数上限清单」逐页给出。
- **模块 README Summary**：默认不超过 100 词；英文按空格分词，中文每 2 个非空白字符计 1 词，中英混排分别计算后相加。提案第 5 节可覆盖该默认值。
- 两种度量用途不同，实现检查时不得混用。

## 调整原则

- 标注「建议值」的是下限或参考线，不满足时写判断依据，不为达标而凑数。
- 标注「默认上限」的可由提案覆盖，覆盖时写明理由和影响。
- 标注「硬约束」或「固定流程上限」的只用于机械判定或流程控制，不随项目调整。
