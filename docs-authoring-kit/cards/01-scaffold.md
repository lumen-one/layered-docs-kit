# 任务卡 01：搭骨架

## 目标

把契约落成真实文件：能导航、能复制、能约束下一次提交。骨架只建现在有内容的层，不提前占地。

## 输入

- `docs-notes/charter.md`：读者、关键事实、启用层级、语言、硬规则初稿。
- 现有目录与代码模块；模块少时逐个看，模块多时先看入口和边界。
- `reference/layering.md` 的「从四层起步」「加层触发条件」。
- `reference/templates.md` 的根 README、架构页、模块 README、`AGENTS.md` 文档段。

## 做法

按这个顺序建，前一步没通就不要做下一步：

1. **根 README**：一段话说明是什么，一段快速开始，一个文档地图（三到五行链接）。这是唯一入口。
2. **`AGENTS.md` 文档段**：写硬规则、维护规则表指针、日常写文档的触发点、升级信号指针。控制在一屏内，细节链接到 `docs/`，不复述。
3. **`docs/architecture.md`**：一页系统地图。组成、每块的职责与边界、主调用链、扩展点。没有的模块先写「待建」，不要编造。
4. **`docs/decisions/README.md`**：说明路径格式与状态，不放空记录。有第一个真实决策时再建记录文件。
5. **模块 README**：只给已有代码、且有对外契约的模块建。没有契约的内部目录不建。
6. **模板**：把 `reference/templates.md` 里用得到的模板落到 `docs/templates/` 或项目约定的模板目录。模板只放结构，不写项目内容。

已存在同名文件时，合并内容而不是覆盖；冲突的规则保留原文，在回报里标出来交给用户决定。

## 产物

- 根 `README.md`
- `AGENTS.md`（新建或合并出文档段）
- `docs/architecture.md`
- `docs/decisions/README.md`
- 已有模块的 `README.md`
- 需要复制到项目里的模板
- `docs-notes/scaffold-report.md`（可选，一页以内），记录建了什么、没建什么、为什么

## `AGENTS.md` 文档段写什么

给一个可以直接抄的骨架，按项目改：

```markdown
## 文档

- 文档入口：`README.md` → `docs/architecture.md` → 各模块 `README.md`。
- 一个事实只在一个地方定义，其他位置放链接。
- 主文档只写当前状态；历史与取舍进 `docs/decisions/`。
- 改配置、对外行为、目录或包名时，同一次改动更新对应文档。
- 定不下来的事写「待确认」，不要编。

触发点：新配置 → 模块 README 配置表；对外行为 → 模块 README 语义与限制；长期取舍 → `docs/decisions/`；移动目录 → 全仓链接。

升级信号：出现第二维护者、首次对外发布、同一事实开始两处各写、模块多到一页放不下时，回撰写套件走一次 03 自查。

维护规则表：见 `docs/maintenance.md`（标准档再建）。
```

规则数量和具体条款按项目定。这一段太长就说明写早了。

## 完成标准

- 从根 README 出发，经文档地图能到达架构页和每一个已存在的模块 README，链接都点得通。
- `AGENTS.md` 文档段一屏内读完，没有复述 `docs/` 里的细节；触发点和升级信号各有一行，不回读 skill 也知道往哪写。
- 没有空目录、空模板、占位页面；建了的每个文件都有真实内容。
- 模板复制到新位置后，按结构就能写，不需要临时补章节。
- 存量文件没有被覆盖，合并与冲突都已记录。
