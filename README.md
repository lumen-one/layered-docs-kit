# 文档管理套件

一套引导型提示词：把项目的零散文档整理成分层、可导航、可持续维护的体系。可以单会话一次做完，也可以拆成主会话加子会话分批执行。方法按项目取舍，这里只写目标、输入、产物和边界。

## 目标

读者从少数入口就能找到需要的事实；同一事实只有一个归属页；能机械判定的规则由检查兜住，判断类规则交给评审；重要取舍留下决策记录。做到这几点就够了，层级多少、批次多大都可以按项目调整。

## 输入

- 项目现有文档：根 README、`docs/`、模块说明、历史文档。
- 代码与构建：模块边界、配置项、命令、CI 与 lint 入口。
- 用户回答：读者是谁、要不要多语言、本次覆盖范围、文档所有者与例外审批人。

## 产物

`docs-plan/` 放过程产物：现状评估、架构提案、批次报告、检查报告、审计报告。项目内放最终体系：指令文件、架构页、模块 README、参考与教程、决策记录、检查脚本。过程产物是施工记录，不需要跟着体系长期维护。

## 边界

全文只有这四条是硬边界：

1. 只改当前任务允许的路径，范围外文件不动。
2. 删除文件或目录前先问用户。
3. 不编造证据、结论或文件内容；写不出证据就写「待确认」。
4. 需要用户决策时停下来问，不自行假设。

其余都是建议。遇到本文件没覆盖的情况，按目标自行判断。

## 六个阶段

| 阶段 | 任务卡 | 主要产物 |
|---|---|---|
| 现状评估 | `cards/00-recon.md` | `docs-plan/recon.md` |
| 架构提案 | `cards/01-proposal.md` | `docs-plan/proposal.md`、批次清单 |
| 层级与规则 | `cards/02-skeleton.md` | 项目内层级、模板、指令文件、`docs-plan/skeleton-report.md` |
| 迁移 | `cards/03-migrate.md` | 批次内文档、`docs-plan/migrate/<批次>.md` |
| 自动检查 | `cards/04-checks.md` | 检查脚本与夹具、`docs-plan/checks-report.md`、`docs/checking.md` |
| 审计与交付 | `cards/05-audit.md` | `docs-plan/audit-report.md`、交付物五项 |

顺序通常如此，可以裁剪：没有存量文档可跳过迁移；用户明确接受不建自动检查时跳过检查，把评审清单写进交付物。

## 派发

主会话读本文件和 `docs-plan/state.md`，一次派一个任务；子会话只读一张卡、卡内「输入」列出的参考与前置产物。任务卡已经写清目标、输入、产物和完成标准，不需要另加流程说明。

```text
你是「文档体系建立」的子会话，任务：<阶段名>。
项目根：<绝对路径>
任务卡：<套件内任务卡路径>

读：任务卡本身，以及卡内「输入」列出的参考与前置产物。
写：卡内「产物」列出的路径，其他文件不动。

完成后回报：产物路径；哪几条完成标准没做到；需要我决定的事。
```

没有子代理时，开新会话粘上面这段即可。只能单会话时，按阶段顺序自己执行，每阶段结束对照卡内「完成标准」自查，然后进入下一阶段。上下文接近上限时，把当前产物和未决问题写进 `docs-plan/`，新会话读进度表继续。

## 进度

把 `state-template.md` 复制成 `docs-plan/state.md`，每阶段一行，写清产物路径和一句备注。它只帮你记住做到哪，不控制流程。

## 提交

每个阶段（迁移按批）完成后由用户提交；提交前不开始下一阶段。用户明确授权时主会话可代提交。

## 文件

```text
README.md                 入口：目标、输入、产物、边界、派发与文件清单
state-template.md         进度表模板
cards/
  00-recon.md
  01-proposal.md
  02-skeleton.md
  03-migrate.md
  04-checks.md
  05-audit.md
reference/
  layers.md               作用域、分层模型、README 契约、写作与维护规则
  decisions.md            决策记录的路径、结构、写作与归档
  bilingual.md            双语三件套与结构镜像
  checks.md               可自动判定的检查清单与扫描范围
```

档位只是建议：`basic` 用最少的层级和检查起步，`medium` 加上决策记录与评审规则，`multilingual` 再加双语配对。不追求一步到位，先跑通再加。

套件同级可能有一份单体版 `documentation-management-prompt.md`；能单会话一次做完时用它更省事，本套件拆开是为了让每次会话的负载更小。
